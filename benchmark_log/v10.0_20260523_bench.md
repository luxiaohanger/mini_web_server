### 5.3 热点摘要

> 符号表：**§0 CPU 预算（Self 互斥）→ §1 server（All 定优先级）→ §2/§3 kernel → §4 libc**。调用链看火焰图。完整符号表见 `benchmark_log/artifacts/v10.0_perf_report.txt`。

**§0 预算（Self）**

| Self | 层级 | 说明 |
|------|------|------|
| 60.5% | kernel | PC 落在内核；见 §2/§3 |
| 25.9% | libc | readv/write/epoll/pthread/malloc（§4 top：`write` 4.5%、`readv` 4.3%） |
| 10.2% | server | PC 落在 server 二进制 |
| 3.2% | libstdc++ | `std::function` / future 等 |

**§1 server（All / Self）**

| All | Self | 符号 | 说明 |
|-----|------|------|------|
| 62.4% | 0.20% | `EventLoop::loop` | 总入口 |
| 32.6% | 0.00% | `onHttp` → `sendHttpOnLoop`（inlined 链） | HTTP 处理 + 写回 |
| 15.1% | 0.40% | `ThreadPool::enqueue` / future 包装 | I/O → worker 双跳 |
| 8.2% | 0.32% | `Connection::onHttp` | 业务入口 |
| 4.5% | 0.45% | `HttpProcess::parse` | Echo 下解析非主矛盾 |

**§3 内核分类（Self）**

| Self | 类别 | 代表符号 |
|------|------|----------|
| 36.0% | other | `_raw_spin_unlock_irqrestore`、锁/原子 |
| 13.0% | network | `tcp_recvmsg_locked`、`tcp_sendmsg_locked`、`net_rx_action` |
| 7.6% | syscall | `do_syscall_64`、`__x64_sys_futex`、`__x64_sys_write` |
| 2.3% | sched | `finish_task_switch`、`schedule` |
| 1.6% | futex | `futex_wake`、`futex_hash` |

火焰图：`onHttp` → `enqueue` → futex；`sendHttpOnLoop` → `bufferToSck` → `write` → `tcp_*`。

## 6. 分析结果

- **结论**：v10.0 验收通过——KA 主基线 **~32.8k RPS**（§4 -t2 -c20 -d30s），相对 v9 同场景 **29154 → 32820（+12.6%）**；短连接轻量用例 SSH 稳定（close -t1 -c5 **~3.65k RPS**）。perf 显示 CPU 主要在 **内核 loopback 栈 + 锁/原子（§3 other 36%）** 与 **libc I/O（26% Self）**；server Self 仅 ~10%，§1 All 最热为 **EventLoop::loop** 与 **onHttp → enqueue 双跳**，`HttpProcess::parse` All ~4.5% 非主瓶颈。
- **异常**：close -t1 -c10 出现 **read 3**；perf 同跑 wrk RPS **41510**（§5.2，RelWithDebInfo + perf 开销，**预期**，不作版本验收）。
- **下一步**：实施 **v10.1**（须 src 变更后升版）——I/O 直出静态 GET、写路径减拷贝、ThreadPool 唤醒与 future 包装瘦身 → 新建 v10.1 报告并 wrk 复测。
