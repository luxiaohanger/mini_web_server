## 6. 分析结果

- **wrk**：KA 正式基线 **69586 RPS**（第 4 节 -t2 -c20 -d30s）；相对 v10.0 **32820（+112%）**；延迟 avg **284us**（v10.0 611us）；close 与 v10.0 同级。
- **符号 §0**：**kernel 66%** ↑（v10.0 60%）、**server Self 8%** ↓（v10.0 10%）——用户态变轻后 **内核/network 分母上升**，非退化。
- **符号 §1**：All 最热 **onHttp(60%) → trySendToSck/bufferToSck(50%/44%)**、**sckToBuffer(25%)**；**enqueue/ThreadPool 归零**；**TimerQueue::refreshClock(11%)** 为 src 下一优先项；`parse` All 6.2% 仍低于读写。
- **符号 §2**：**network 20%** ↑（v10.0 13%），与 RPS 翻倍、loopback TCP 吞吐匹配；**futex/sched** 近零，印证关池去锁。
- **符号 §3**：**io 8.9%** 以 **readv** 为主（write 2.6%）；**pthread 1.3%** ↓（v10.0 6.2%）；**timer 4.1%** 与 idle 刷新一致。
- **综合结论**：关 ThreadPool 同时兑现 **wrk +112%** 与 **符号表去双跳**；新瓶颈在 **内核 network + 读写 syscall** 与 **Timer 刷新**。
- **异常**：close read 4；perf 同跑 wrk RPS 高于 Release 纯 wrk 为预期。
- **下一步**：v10.2 优先 **Timer 刷新降频/合并**、写路径减拷贝；重业务再 `-t on`。
